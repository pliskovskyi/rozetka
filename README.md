# Автооновлення прайсу для Розетки

## Що це

Раз на годину бере актуальні ціни та залишки з Хорошопа і переписує
`price_rozetka_1.xml`. Розетка забирає цей файл за своїм розкладом
(60 хвилин, налаштовано в кабінеті продавця).

## Ланцюжок

```
Хорошоп
   ↓  Prom-фід (автогенерація увімкнена)
GitHub Actions  — щогодини о :20
   ↓  перерахунок ціни +20,5 %, округлення до найближчих 5 грн
price_rozetka_1.xml  (коміт у цей репозиторій)
   ↓  раз на 60 хв
Кабінет Розетки
```

## Джерело даних

```
https://techfil.com.ua/content/export/1ea2a9dbded31e6279a51939d1a50079.xml
```

Хорошоп → Товари → Експорт → «Площадка: Prom (ua+ru)».
Віддає по кожному товару: артикул, ціну, `quantity_in_stock`, `available`.
Публічний, без авторизації.

**Важливо:** у цієї вигрузки має бути увімкнена автогенерація.
Якщо вимкнути — файл замерзне, і скрипт возитиме старі дані.

## Формула ціни

```
ціна Розетки = ціна Хорошопа × 1,205, округлення до найближчих 5 грн
```

Округлення half-up: рівно половина йде вгору (602,50 → 605).

Перевірено на живих даних:

| Хорошоп | Розетка |
|---|---|
| 575 | 695 |
| 690 | 830 |
| 500 | 605 |
| 518 | 625 |
| 615 | 740 |
| 1560 | 1880 |

Береться поле `<price>` — це фактична ціна продажу.
Якщо на товарі акція, у фіді є ще `<oldprice>` (перекреслена стара ціна) —
скрипт її ігнорує. Приклад: ABS Темно-Сірий, `oldprice=690`, `price=518` →
у Розетку йде 625, а не 830.

## Що саме змінюється у файлі

Тільки три речі в кожному `<offer>`:

- атрибут `available`
- `<price>`
- `<stock_quantity>`

Склад товарів, назви, описи, характеристики, категорії, картинки —
не чіпаються. Новий товар у файл сам не додається: його треба
додати вручну один раз, далі ціна й залишок оновлюватимуться самі.

Товар, якого немає у фіді Хорошопа, залишається у файлі без змін.

## Захист від дурних коммітів

- Якщо Prom-фід недоступний або порожній — скрипт падає й **не чіпає файл**.
- Якщо жодне значення не змінилося — коміту немає.

## Ручний запуск

Actions → «Оновлення прайсу для Розетки» → Run workflow.
У логу видно кожну зміну рядком:

```
PETG074-1000-BLACK   ціна 695 -> 695  залишок 198 -> 193  наявність true -> true
```

## Файли

- `update_price.py` — скрипт
- `.github/workflows/update-price.yml` — розклад

## Перевірено перед запуском

- 20 з 20 товарів зіставилися з фідом Хорошопа
- diff після прогону — 24 рядки: тільки `price`, `stock_quantity`,
  `available` і дата у шапці. Решта файлу байт у байт
- повторний запуск не робить нічого («Змін немає»)
- недоступний фід — файл не чіпається
- порожній фід — файл не чіпається
- результат перевіряється на валідність XML і на кількість `<offer>`
  перед записом
